# LOOP

**Telegram Attention Layer**: сообщения → незакрытые договорённости → действие и память.

LOOP не пытается стать ещё одним task manager. Он отвечает на вопрос: **что из Telegram реально требует моего внимания и что я захочу вспомнить позже?**

## Что уже работает

- Forward Mode: пересылка чужих Telegram-сообщений боту.
- Текст, voice, audio и video note / кружки.
- Groq Whisper → транскрипт → смысловые объекты.
- Одно сообщение может породить несколько объектов.
- Новое ядро договорённостей: отдельно определяются смысл (`kind`), подтверждение (`agreementStatus`) и следующий шаг (`nextAction`).
- Предложение встретиться или вместе посмотреть фильм = одна карточка **«Договориться»**, а не рекомендация в памяти. Подтвердить можно кнопкой **«Договорились»**.
- Для несогласованной встречи дата хранится словами (`whenText`), но автоматическое напоминание и календарное событие не создаются до уточнения деталей.
- Старые карточки остаются совместимыми и не меняются автоматически: новый разбор применяется к новым пересылкам.
- Типы: `reply`, `todo`, `waiting`, `event`, `saved`.
- Извлечение даты/времени и персональные Spaces: Дом / Работа / Личное + свои темы с описанием правил.
- Если тема неоднозначна, объект остаётся **Без темы** и показывается вверху «Сегодня» → «Нужно распределить».
- Исправленная вручную тема сохраняется как пример для будущей AI-классификации **этого Telegram-пользователя**. Примеры ограничены по количеству, не используются для обучения модели.
- Space можно переименовать или удалить: при удалении задачи сохраняются, но становятся нераспределёнными.
- Today: активные хвосты, Done, snooze до завтра.
- People: незакрытое, сохранённое и история по человеку.
- Memory: гибридный локальный + AI поиск по словам и смыслу.
- Evidence: исходное сообщение / транскрипт хранится рядом с объектом.
- Google Calendar template для событий.
- Telegram Mini App auth через проверенный `initData`.
- Данные разделены по Telegram user id.
- Mini App и API могут работать с одного Node-процесса.

Bot: `@loop_attention_bot`

## Локальная разработка

```bash
cp .env.example .env
npm install
npm run build
```

Три терминала для разработки:

```bash
npm run bot
npm run api
npm run dev
```

Локальный браузер работает без Telegram auth. Если `LOOP_DEV_USER_ID` не задан, dev API показывает все локальные тестовые записи. В production такого fallback нет.

## Выбор AI без лишних расходов

LOOP поддерживает два **текстовых** провайдера. По умолчанию остаётся
`AI_PROVIDER=groq`, модель `openai/gpt-oss-120b`. Новый вариант:
`AI_PROVIDER=openai`, модель `gpt-6-luna`. Модель запускается на
**сервере**, ключи никогда не отправляются в Mini App. Поиск по смыслу
использует того же текстового провайдера. Распознавание голосовых остаётся
в Groq Whisper и требует `GROQ_API_KEY` в любом режиме.

Это не одна подписка: ChatGPT и OpenAI API оплачиваются отдельно.
Можно протестировать тексты в ChatGPT вручную, но приложение не может
бесплатно отправлять запросы через текущую переписку ChatGPT.
Не подключай OpenAI API до сравнения. При первом пополнении баланса
отключи автоматическое пополнение и установи лимиты расходов в кабинете.

Одинаковые тестовые сообщения находятся в `tests/ai-eval.json`.
По умолчанию команда ничего не отправляет и не списывает денег:

```bash
npm run eval:ai
```

**Платный/тарифицируемый прогон только по явной команде:**

```bash
npm run eval:ai -- --live --provider=groq --max=5
npm run eval:ai -- --live --provider=openai --max=5
# Только при наличии обоих ключей:
npm run eval:ai -- --live --provider=both --max=5 --max-usd=0.05
```

Скрипт сравнивает тип, смысл, статус договорённости и следующий шаг;
показывает исходную классификацию модели и итог после защитных правил,
`usage` в токенах и примерный расход на запрос. `max-usd` ограничивает
**планируемый** тест на основании уже полученной статистики, не является
жёстким ограничителем у провайдера. Есть пауза между запросами, чтобы
не упираться в бесплатные лимиты Groq. Запуск с `--live` не использует
личные сообщения из базы, только синтетические и обезличенные кейсы.

Ориентир цен (USD за миллион обычных входных / выходных токенов,
без кэша, 11 октября 2026): Groq GPT-OSS 120B $0.15/$0.60,
OpenAI GPT-6 Luna $0.10/$0.50. Таблица живёт в
`server/ai-provider.mjs`, фактические счета могут отличаться.
Официальные цены: https://console.groq.com/docs/model/openai/gpt-oss-120b
и https://developers.openai.com/api/docs/models/gpt-6-luna .
**Ни один платный запрос из CI не запускается.**

## Исправление смысла

В деталях карточки нажми **«Исправить смысл или название»**.
Можно вручную выбрать «Нужно договориться», «Встреча согласована»,
«Нужно сделать», «Ответить», «Жду другого человека» или «Сохранить».
Название тоже редактируется. Исправление обновляет текущую карточку
и сохраняет приватный пример для будущих классификаций.
Файл: `server/data/meaning-corrections.json` (или на persistent volume),
изолирован по Telegram user id. Хранятся максимум 20 последних исправлений
на пользователя, только 3 подходящих примера добавляются в AI-промпт.
Это контекст для модели, не обучение её весов; 100% точности не гарантирует.

## Проверка договорённостей

Перешли боту:
- «Давай в субботу встретимся и посмотрим фильм» → одна карточка **Договориться о встрече в субботу**, следующий шаг: согласовать детали, встреча ещё не подтверждена.
- «Ксюш, сегодня у мамы день рождения, давай завтра тебе его привезём» → одно предложение о передаче вещи, дата **завтра** (не сегодня), нужно подтвердить и уточнить место; место не выдумывается.
- «Посмотри сериал Тьма, советую» → **Память**, без поручения встретиться.
- «Договорились, встречаемся в субботу в 19:00» → подтверждённое событие.

В деталях предложения нажми **Договорились** или **Неактуально**. Действия сохраняются в существующем JSON-хранилище. Старые карточки намеренно не мигрируются автоматически. Автоматическое объединение переписок нескольких людей и полноценные просроченные обязательства пока не реализованы.

Проверка кода без запроса к Groq: `npm test`. В тестах есть реальные ошибки классификации и имитация неверного JSON-ответа Groq. После изменений `npm run build`.

## Проверка персональных Spaces

Открой «Сегодня» → **+ Space**. Назови, например, «Футбол», и напиши,
что сюда относить («тренировки, матчи, команда»). Для новых пересылок
LOOP использует название, описание и предыдущие ручные исправления.
Уверенность в Space оценивается отдельно от уверенности в самой задаче.
Неоднозначное «завтра собрание в 9» не должно автоматически попадать
в «Работа» или «Личное».

Задачи **без темы** видны сверху «Сегодня», если выбрано «Все».
Назначь Space прямо там или в деталях любой карточки. Исправление
запоминается на этом аккаунте. Старые ошибочные категории не меняются
автоматически, но их можно исправить вручную. Если переименовать
Space, связанные задачи перейдут в новое название. Удаление Space не
удаляет задачи: у них будет «Без темы».

Данные правил и примеров лежат в `server/data/spaces.json` рядом с
`loops.json` (или на Railway Volume) и разделены по Telegram ID.
Исходный текст примеров может повторно отправляться в Groq для
классификации новых сообщений. Проверка: `npm test`, `npm run build`.

## Быстрая проверка на телефоне (реальные задачи)

MacBook и телефон должны быть в одной Wi-Fi сети. В локальном режиме нужна заполненная
`.env` с `BOT_TOKEN`; для AI-классификации нужен также `GROQ_API_KEY`.

```bash
npm run build && npm start
```

Открой на телефоне `http://<IP-MacBook>:8787/`. Это один сервер: интерфейс,
API и бот запускаются вместе. Посмотреть IP можно командой
`ipconfig getifaddr en0`. При тестировании через обычный браузер
`NODE_ENV` не должен быть `production`: в production доступ к данным
требует подлинный Telegram Mini App `initData`.

Если нужен горячий перезапуск интерфейса: в двух терминалах запусти
`npm run api` и `npm run dev -- --host 0.0.0.0`. Vite отправит запросы
`/loops`, `/memory/search`, `/me`, `/health` в локальный API через
proxy, поэтому на телефоне не нужен `localhost:8787`.
Если в старой `.env` остался `VITE_API_URL=http://localhost:8787`,
он игнорируется в пользу того же origin.

В настоящем Telegram Mini App нужен публичный HTTPS-адрес и
`WEB_APP_URL` с этим адресом. Обычный LAN HTTP годится только для теста
в браузере.

## Постоянный HTTPS запуск в Telegram (Railway)

Для закрытого пилота достаточно **одного** Railway-сервиса: фронт, API и
бот работают через `npm start`. Домен и сертификат выдаёт Railway.

1. Railway → New Project → Deploy from GitHub repo →
   `volkovasen/loop-telegram`. В Settings → Source выбери ветку
   `feat/mvp-forward-loop-ui` (не `main`).
2. Установи команды: Build **`npm run build`**, Start **`npm start`**.
   Нужен Node.js 22+; `PORT` Railway выдаёт автоматически.
3. В Variables задай **`NODE_ENV=production`**, **`BOT_TOKEN`**,
   **`GROQ_API_KEY`**. Эти значения вводи только в Railway, не в GitHub.
   Не задавай `VITE_API_URL`, чтобы Mini App и API использовали общий домен.
4. Добавь к сервису **Volume** с mount path **`/data`** до первого запуска.
   Иначе LOOP в production намеренно откажется стартовать, чтобы не
   потерять сообщения после нового деплоя. `DATA_DIR` не нужен: путь к
   подключённому диску определяется автоматически.
5. В Settings → Networking → Public Networking выбери **Generate Domain**.
   Получишь HTTPS-адрес `https://…up.railway.app`. После выдачи домена
   запусти Redeploy, если бот был запущен раньше.
6. Проверь `https://…up.railway.app/health` (должно вернуть `ok: true`).
   В `@loop_attention_bot` открой **/app** или кнопку **«Открыть LOOP»**.
   Бот сам назначает меню на Railway-адрес при запуске.
7. Перешли боту настоящее сообщение. Оно должно появиться в **Сегодня**,
   а «Готово» должно сохраняться после повторного открытия приложения.

Проверь, что у сервиса **одна реплика**: у нас Telegram long polling и
JSON-хранилище, не горизонтально масштабируемый backend. Перед пилотом
сохрани резервную копию `loops.json` с volume.

**Ограничения:** постоянный сервер может выйти за бесплатные кредиты
Railway; проверь расход и лимиты в кабинете. До подключения Railway и
первого деплоя приложение не будет доступно постоянно. Вне Telegram
production API возвращает 401, это ожидаемо.

## Production

Нужны минимум:

- `BOT_TOKEN`
- `GROQ_API_KEY`
- `WEB_APP_URL=https://...`
- `NODE_ENV=production`
- `CORS_ORIGIN=https://...`

Сборка и запуск:

```bash
npm ci
npm run build
npm start
```

`npm start` поднимает одновременно:

- Telegram bot long polling;
- API;
- собранный Mini App из `dist/`.

Проверка сервиса:

```text
GET /health
```

После запуска бот сам ставит `/app`, `/help` и кнопку Mini App, если задан `WEB_APP_URL`.

## Безопасность

- `.env` и `server/data/` не коммитятся.
- Production API не принимает запросы без валидного Telegram Mini App `initData`.
- Пользователь видит и меняет только свои объекты.
- `ownerId` нельзя поменять через PATCH.
- Запись JSON делается атомарно и последовательно, чтобы параллельные сообщения не перетирали данные.

> Текущее JSON-хранилище подходит для закрытой беты. Перед массовым публичным запуском его нужно заменить на постоянную БД с резервными копиями, не меняя продуктовую модель.

## Product boundary

Сейчас сознательно не делаем:

- автоответы от имени пользователя;
- CRM с полями и воронками;
- канбан / проекты;
- Gmail / Notion / Slack;
- фейковый доступ к телефонной книге Telegram;
- passive capture без отдельного privacy-дизайна.

Следующий инфраструктурный слой после закрытой беты: Telegram Chat Automation / Secretary Mode и нормальная production DB.
